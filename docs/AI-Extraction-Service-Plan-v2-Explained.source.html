1. Summary — what changes and why

The Phase 1 plan is sound in its shape: a .NET service on Azure App Service accepts documents from legacy MVC 4.8 applications, queues them in Azure SQL, has Azure AI Document Intelligence extract them with custom neural models, and returns canonical JSON v1 through an HMAC-signed webhook. The review kept that shape. What it found are defects in the details that would lose results, bill wrongly, or fail at deployment.

The eight changes that matter most

ChangeProblem in v1Fix in v2
High Lease tokenUpdates check only Status = 'Processing'. A worker that lost its lease still writes: it can double-POST to Azure or overwrite another worker's state.A new LeaseToken on every claim; every write checks it. Zero rows = lost ownership, stop.
High Run numberA late job.failed from an earlier attempt can mark the retried document Failed; the later success is then ignored. The result is lost.RunNo on jobs, events, results and the consumer row. Outcomes apply only to the exact bound run.
High Azure operations tableOne Operation-Location column for two calls (classify, then extract). A crash mixes them up; classifier pages are lost from billing.AzureOperations: one row per Azure call, written before the POST.
High Ledger per operationBilling is written only when a job completes. Azure work billed on failed jobs never reaches the ledger. A missing price silently drops the row.Ledger row when an Azure operation succeeds, whatever the job outcome. Missing price stops and alerts.
High Pilot upload authorizationDocsInController.UploadFile() has no authorization. Anyone could send billable documents.[Authorize] on that one action; Submit refuses an anonymous user.
High SQL permissionsA pipeline with only db_ddladmin cannot create users or grant roles; the app's db_datawriter can rewrite the "append-only" ledger.Bootstrap by an Entra admin (WITH OBJECT_ID); custom docai_runtime role with INSERT-only ledger.
High Always On + .NET 10The worker runs inside the web app; without Always On the app unloads after ~20 idle minutes. .NET 9 support ends 10 Nov 2026.alwaysOn: true; liveness health check; target .NET 10 LTS.
High Consumer dedupeThe same file on two operations returns the first operation's row; the second operation loses its link.Consumer dedupe adds the business entity and the shipping line.

What stays exactly as designed

  • Asynchronous request-reply with the SQL Jobs table as the queue, claimed with ROWLOCK, UPDLOCK, READPAST (an extra test runs it with Azure SQL's default READ_COMMITTED_SNAPSHOT ON).
  • Managed identity to every Azure resource, local authentication disabled and enforced by Azure Policy.
  • HMAC-SHA256 over "{timestamp}.{rawBody}", two secrets during rotation, registered callback URLs (no SSRF).
  • One transaction for outcome + result + ledger + webhook outbox; idempotent intake by file hash; 404 for another consumer's job.
  • The kit footprint: a folder of four files in the existing web project, one table, settings, one route — no new project.

Rounding each consumer's infra share to the nearest cent separately gives 24.24 + 16.16 + 20.20 + 12.12 + 16.16 + 12.12 = $101.00 against a bill of $100.99. 18. Month end, reconciliation gate and capacity cost

18.1 Month-end procedure (operator, about 15 minutes)

  1. A few days into the next month, take from Cost Management (rg-docai-prod): extraction cost and quantity, classification cost and quantity, everything else; convert each meter's unit to pages. Take the dev DI cost from rg-docai-dev.
  2. [B2] Insert the BillingPeriods row. Any later correction of its numbers clears ReconciledAtUtc.
  3. [B3] Reconcile both meters. A meter passes when the ledger is within ±2 % of Azure; zero on both sides passes; ledger pages with zero Azure pages always fail. [B3] also lists the month's Unknown Azure operations (calls that may have been billed without a result). Passing sets ReconciledAtUtc — the hard gate.
  4. [B4] Close the month: refused unless reconciled; allocation in cents with largest remainder; costs of a meter that no consumer used go to UnallocatedUsd; a closed month cannot be closed twice.
  5. [B5] / [B6] Publish the statements: per consumer, subtotal per company, per product, grand total.
  6. Chargeback (later): a price plan on top of the cost; cost and price stay separate numbers.

[B7] corrections: a negative row that reverses one ledger row; a unique index allows only one reversal per row; the reversal is booked in the current open month.

18.3 Cost controls

  • Idempotency: the same file, for the same consumer, document type and requested line, is analyzed once. A new analysis needs a Failed job or an explicit reprocess.

Code rules for the kit (legacy ASP.NET)

  • The pilot's <httpRuntime> has no targetFramework, so ASP.NET runs its legacy synchronization context. Kit I/O uses ConfigureAwait(false) and reads every request value (HttpContext.Current, headers) before the first await.
  • TLS: add TLS 1.2 only when the process is not on SystemDefault — |= on SystemDefault (0) would pin the whole process to TLS 1.2 and stop OS negotiation of newer protocols. The setting is process-wide.
  • One static HttpClient; ConnectionLeaseTimeout of 5 min on the DocAi endpoint so DNS changes are picked up; per-call CancellationTokenSource with a 120 s transfer budget (20 MB over a 5 Mbps uplink takes at least 32 s — v1's 30 s timeout would fail every time).
